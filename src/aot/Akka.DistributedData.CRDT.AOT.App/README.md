# Ordinary public CRDT native consumer

This consumer references Akka.DistributedData through an ordinary assembly identity. It uses
public domain constructors, public delta operations, the existing public serializer-alias
lookup and public id-based reads. It has no friend identity, private codec references,
reflection, blanket roots, new registry or product changes.

It requires an actual Native AOT executable and `Akka.DynamicTypeLoading=false`. The existing
log watchdog checks startup, serialization and shutdown and fails on any warning/error log. Three local
actor systems use the global switch off, on and on with an explicit whole-protocol legacy
pin. Each checks actual writer selection and both registered reader IDs. The id 51 alias
must expose `SerializerV2`; every supported case invokes its native buffer writer and reads
an input with two sequence segments, including fieldless messages.

## Supported corpus

The 69 cases per mode cover public GCounter, PNCounter, Flag and VersionVector forms;
GSet/ORSet/LWWRegister closed over int, long, string and IActorRef; their supported keys;
and public remove/full/group delta operations. Inputs use fixed nodes, timestamps and
causal maps. Multi-node counters include `ulong.MaxValue`; registers include timestamp
extremes. Domain equality includes the complete causal state, with exact runtime type
checks because key equality alone compares only the string id. Applicable deltas also
compare their state after application from Zero.

Actor-reference cases use the local system's DeadLetters, and a NoSender set checks the
provider's legacy empty-path result. They do not establish remote actor reference resolution.
DeletedData and one AddDeltaOperation are bootstrapped through supported public legacy reads;
their private concrete types are never named by this app. The deleted singleton keeps its
original identity; the add control must produce its fixed complete public ORSet state.

`FrozenRecords.cs` copies 31 selected historical id 11 records and 25 valid id 51 generic
rejection records from reviewed checkpoint `73b6a4bbc1a8b6618fc5974ac47b1900b85f2ed0`.
The original annotated fixtures retain capture provenance in
[`Snapshots/README.md`](../../contrib/cluster/Akka.DistributedData.Tests/Serialization/Snapshots/README.md).
The untouched legacy serializer blob is `fa026096a77483a9df68cd71b707ac6ca9ac213b`.
Historical reads assert fixed values, exact kinds, complete delta application state and,
for the three remaining delta controls, every original byte on re-encoding. They are
independent immutable records, not bytes generated by the current writer during the proof.

The old generic b/c/e/j key readers, arbitrary generic reconstruction and historical remote
reference fixtures are excluded. This consumer does not convert those boundaries into
successful reads by catching their failures. Canonical protobuf reconstruction and generic
maps remain separate dynamic paths; there is no whole-Sharding or general native DData claim.

## Rejection and application ownership controls

Fourteen public unsupported shapes per mode reject before caller output or application
payload callbacks. All 25 frozen generic V2 shapes reject on cold direct, segmented and
registered-id reads. A derived negative register packet retains real application payload
bytes, places them before its unsupported descriptor, and must reject before the reader
callback. This packet is explicitly synthetic negative input, not historical writer output.

The application independently registers id 777 for its payloads. A known string register
must invoke that exact writer and reader; a late payload failure must preserve pre-existing
caller bytes. Unknown manifests reject through both the direct id 51 reader and the real
module's public id-based entrypoint. Native execution cannot warm a dynamic generic cache;
the separate managed checks own warm-cache coverage.

The required completion marker is:

```text
[crdt-public-native] OK cases=207 native-writes=207 segmented-reads=207 historical-reads=93 generic-writes-rejected=42 generic-reads-rejected=75 ownership=3 atomic=3 guarded-callbacks=6 unknown-manifests=6
```

## Reproduce

Use an isolated checkout and SDK 10.0.114. The app pins runtime/compiler pack 10.0.14 and
keeps AOT settings local to RID-specific publishes. The script selects SDK 10.0.114 from
an artifact work directory so the base branch's older repository pin cannot silently win.

```bash
AKKA_NATIVE_DOTNET=/path/to/dotnet \
  bash src/aot/Akka.DistributedData.CRDT.AOT.App/reproduce.sh \
  /tmp/crdt-public-native-proof
```

The script checks the managed build, cold-publishes this app, requires the exact native
marker, and compares visible warnings using the repository's existing warning checker.
Do not build the same checkout concurrently. Its artifact path must be outside this app's
bin/obj directories because those generated outputs are cleaned for the cold publish.

## Evidence and limits

The initial and final native executions passed on SDK 10.0.114/runtime 10.0.14. Root review
required installing/checking the already-linked log watchdog; the final cold expanded CI
replay passed with startup, serialization and shutdown checks enabled. The managed build has
zero warnings/errors and Slopwatch reports zero issues. The initial managed compile tried
an internal id lookup; that consumer mistake was corrected using the existing public alias
overload, with distinct marker types to preserve cache semantics. The original failure
receipt remains retained. No product API or registration change was made.

The ordinary and retained friend publishes emit the same 70 warning lines / 69 normalized
legacy/dependency keys, with zero added/gone keys and zero unlocated diagnostics. None is
attributed to the new MessagePack codec, app, V2 runtime or Shared sources. The comparison
reference is retained as evidence; it is not an approved CI warning baseline. The old
reflection debt remains visible, and this proof does not approve it away.

`evidence` retains compressed full build, publish, run, warning comparison and SDK output,
original failure output, commands and hashes. Hosted CI execution, native Remote/Cluster
startup, transport interoperability, arbitrary payload support and performance acceptance
remain outside this consumer's evidence.
