Keep value-type elements typed between stream stages

Remove repeated boxing in ordinary fused connections while retaining the interpreter’s scheduling, public API and object-based boundaries.

The code change

A fused graph executes multiple stages in one interpreter. Its connections are still separate handoff points. Today a sequence is unboxed when grabbed and boxed again when pushed, even when both stages run in that same interpreter.

Current

// Abbreviated current implementation; guards omitted here.
Push<T>(outlet, value):
    connection.Slot = value;  // T becomes object: struct boxes
Grab<T>(inlet):
    return (T)connection.Slot;

// A forwarding stage repeats that conversion at each hop.
Push(output, Grab(input));

Proposed

// Approved design sketch; guards omitted here.
// Connection remains the existing public sealed class.
// Materialization creates typed storage only for eligible connections.
internal sealed class TypedSlot<T> {
    T Value;
    bool HasValue;            // default(T) remains a valid element
}

Push<T>(outlet, value):
    preserve existing guards, port state and trace capture;
    if connection.Storage is TypedSlot<T> typed:
        typed.Store(value);   // writes a T field; no per-element box
    else:
        store through existing object path;
    schedule the existing Connection;

Grab<T>(inlet):
    preserve existing arrival/failure/completion rules;
    read T from matching typed storage, otherwise object fallback;
    clear consumed payload and appropriate trace state;

// Existing stage code stays the same.
Push(output, Grab(input));

The new holder is allocated once per eligible connection per materialization, not per message. Keeping a reference to that holder in an untyped connection array does not box the T stored inside it. Type checks, state transitions and holder allocation still have costs to measure.

Current payload path

Stage produces sequence value
↓
Connection stores boxed object
↓
Next stage unboxes; its next push boxes again

Proposed eligible payload path

Stage produces sequence value
↓
Connection’s reusable typed field stores value
↓
Next stage reads and writes typed fields

Scheduling, handlers, trace context and backpressure remain with the existing Connection. Completion/failure/cancellation are omitted from this flow and covered below.

Direction and limits

Selected: optimize ordinary fused value-type connections first. Keep the public sealed Connection, exposed Connection[] arrays and object Slot property. Compose internal typed storage into it rather than deriving Connection<T>.

Initially use typed storage only when both actual materialized stage endpoints are standard typed ports with the same value type; an outer graph shape’s typed view is insufficient. Absent, custom, unequal or erased endpoints stay on the object path without runtime reflection. Retain the object path for erased actor/substream boundaries, different visible port types, and external custom ports. Reference-type connections should retain their existing representation. These compatibility paths are permanent where needed, not temporary migration flags.

No design choices are awaiting your answer. Implementation was authorized on 2026-10-14 and is underway in draft PR #8807. The focused implementation checks passed 109/109. Existing benchmark controls and actual Artery allocation profiles have completed; broader same-revision checks remain pending. See the PR description for generated tables and the review findings. Remaining questions—public Slot behavior, exact eligible edge selection, retention, and performance—are engineering checks, not assumptions to waive.

Smaller alternative: transparent stages could forward the existing boxed object without unboxing/reboxing. That retains the first box and requires opting in individual stages, but avoids typed-storage factories. An Artery-only carrier is another smaller option and costs one new object per encoded frame. If typed storage fails its compatibility or performance gates, return to these alternatives with evidence.

Non-goals: making every stream or Artery message allocation-free; changing Graph DSL variance support; changing stream event ordering, public contracts, wire formats or pooled-buffer ownership; redesigning actor mailboxes or substream messages in the first PR.

Responsibilities that must remain intact

  • Retain: Connection identity, event queue, handlers, port-state transitions, backpressure, trace context/links, and public object-facing access.
  • Add: internal typed payload storage and reflection-free creation through existing typed ports; an object-facing compatibility bridge coherent with typed Push/Grab.
  • Remove from eligible normal delivery: payload conversion to object at every handoff. Do not remove supported fallback behavior.
  • Separate payload occupancy from value: zero, default sequences and populated nullable values are data. Null references and empty nullable values remain rejected.
  • Preserve pending data: completion and failure must retain an already pushed, ungrabbed element with existing callback ordering and one-grab behavior, including Grab after OnComplete or OnError. Terminal delivery, connection closure or stage finalization alone must not clear that pending value. Failure reason identity must survive.
  • Clear references: successful consumption, replacement and cancellation paths that previously discarded Slot clear typed payloads and cached compatibility views, including structs containing references. Pull without Grab makes the previous element unavailable but the original object Slot retained it until replacement/cancellation; preserve that same one-payload lifetime. Cancellation after upstream closure likewise must not invalidate a terminal pending Grab.
  • Public Slot bridge: reads/writes and Empty/Failed/Cancelled views must remain coherent. A diagnostic or compatibility read may box on demand; interpreter hot paths must not depend on that view. Repeated reads of a pending typed payload must return the same cached box. An explicit setter must preserve the exact assigned object on reads, accept arbitrary objects without eager conversion, and defer the same conversion errors until Grab. It may use boxed fallback until the next ordinary typed write. Interpret control markers with the existing port-state rules, not merely by the assigned object’s runtime type. Characterization tests must confirm this contract before replacing the backing auto-property.

The factory pattern already exists on Inlet/Outlet for Native AOT-safe boundary creation. Reuse that mechanism with an internal nonabstract fallback; do not add runtime generic reflection for ordinary typed ports.

Evidence, payoff and challenge

Gross removal in the model is roughly 40 B per value handoff. Actual Artery total process allocation is about 300 B/message lower with one lane and 327 B lower with four lanes. Replacement costs include typed storage per connection, dispatch checks, compatibility code and cold-path boxing; Connection grows by 8 B and ElementSlot<int> is 32 B. Net materialization timing is not stable across order reversal, and an integrated throughput improvement remains unproved. Production code grows; no line-count saving is claimed.

What could disprove the recommendation: raw Slot compatibility cannot be preserved without a public/behavioral break; materialization and dispatch costs outweigh the gain for short/reference streams; or Artery’s remaining erased boundaries dominate enough that fused savings do not improve the integrated workload. Those findings block dependent claims and trigger reassessment, not weaker assertions.
