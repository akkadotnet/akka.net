# Trim/AOT warning baseline for the Native AOT canary (src/aot/Akka.AOT.App).
#
# One line per distinct IL2xxx/IL3xxx warning that the canary's ROOTED publish
# (-p:RootAkka=true, which adds a TrimmerRootAssembly for Akka so ILC analyses every path in the
# library rather than only the ones two toy actors reach) still emits from a file under
# src/core/Akka/. Pipe-separated, four components:
#
#   <IL code>|<repo-relative file>|<member that owns the site>|<message, whitespace and digits removed>
#
# The member is empty for the Roslyn analyzer's form of a warning, which carries no member prefix;
# scripts/CheckAotWarnings.cs folds that form into the ILC/ILLink form of the same warning so it is
# never baselined twice. The message is squashed rather than pretty because ILC and ILLink disagree
# about whitespace for the same warning (`GetType(String,Boolean)` vs `GetType(String, Boolean)`),
# and because a digit in the prose must not churn the key.
#
# There is no line number, on purpose: moving a warning site down a few lines is not a change in the
# AOT surface. Both the member AND the message are in the key because neither alone is enough - see
# the two IL2067s on NewtonSoftJsonSerializer.CreateConverter below, same code, same file, same
# member, different callee.
#
# scripts/CheckAotWarnings.cs builds the same keys from the publish log and compares:
#
#   * a warning emitted that is NOT listed here -> the job FAILS and prints the full message. Fix
#     the site, or - if the warning is understood and accepted - add its key here in the same PR
#     with a comment saying why.
#   * a key listed here that is no longer emitted -> the job PASSES and prints the lines to delete.
#     Delete them by hand; there is no rewrite mode, because that would eat the comments below.
#   * nothing in scope at all while this file is non-empty -> the job FAILS, because that means the
#     check measured nothing (skipped ILC, wrong repo root, no PDBs) rather than that core got clean.
#
# What is NOT here, and why. Only files under src/core/Akka/ are compared. Warnings from
# dependencies - Newtonsoft.Json's own code, the BCL - do not reach this file by being filtered on
# their path: ILC has no PDB for them, so it reports them with no source location at all, and the
# checker counts those separately and can never key them. Note the difference from
# src/core/Akka/Serialization/NewtonSoftJsonSerializer.cs, which is core's own source and is very
# much in scope.
#
# The goal is for this file to hold nothing but the header. Every entry below is a place where core
# still reaches for a type by name that the trimmer cannot see. See #7246.
