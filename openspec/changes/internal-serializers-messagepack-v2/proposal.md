## Why

Akka.NET 1.6 makes `SerializerV2` canonical and ships source-generated MessagePack serializers (`Akka.Serialization.V2`, MessagePack-CSharp 3.1.7) validated by `messagepack-sourcegen-validation` (Milestone 3). The internal cluster/replication/delivery/sharding message serializers are still hand-written protobuf (`SerializerWithStringManifest` over `Google.Protobuf`). These run on the hottest steady-state paths in a cluster — gossip, deltas, heartbeats, delivery flow-control, shard routing — and are allocation-heavy (`ToBinary → byte[]` per message, proto object graphs). Migrating them to the validated MessagePack V2 generator should cut CPU and allocations on those paths. Per the maintainer: *if we don't see a very noticeable improvement, we're doing something wrong* — measured improvement is the acceptance gate, not an afterthought.

The migration must be rolling-upgrade safe and reversible: a mixed cluster must never receive bytes it can't decode, and operators must be able to turn it on only when every node can read it.

## What Changes

- **One global opt-in V2 switch, off by default** (amended 2026-10-02; this reverses the 2026-07-18 "no flag" ruling after PR #8403's per-subsystem hook was withdrawn). V2 serializers ship as **read-only rows** in each module's C# serializer table (alias `<legacy-alias>-v2`, id `legacy + 40`, empty `UseFor`), so every node can read V2 as soon as it runs a release that contains them. When the user turns the switch on, each module's V2 row takes over its legacy row's bindings. Legacy rows stay registered forever for reads. Operators turn the switch on once every node runs a version that can read V2: that is docs guidance, not a hard rule in code. The switch's name and shape (a HOCON key plus a `Setup` equivalent) are designed in #8713.
- **No `.conf` rows.** Built-in serializers register only in the C# module tables (#8676). User `serialization-bindings` entries (by alias) and `SerializationSetup` still override the table defaults, which is how an operator pins a subsystem back to legacy.
- For each migrated subsystem, add a **forked** native V2 (source-generated MessagePack) serializer with a new serializer id drawn from the reserved internal block **40-79** (mnemonic: `v2_id = legacy_id + 40`). The legacy serializer and its id are retained, never mutated in place.
- **Both** serializers (legacy id + V2 id) are always registered on every node, unconditionally and forever. Reads dispatch purely by numeric serializer id, so any v1.6 node decodes either format no matter what it writes; the switch only changes which serializer the type→serializer write-side **binding** points at.
- Reuse existing manifest tokens on each V2 serializer so intra-serializer dispatch mirrors its legacy counterpart 1:1.
- **Native route:** Primitive (17), PersistenceMessage (7) and PersistenceSnapshot (8) get no MessagePack port and no new id. Each becomes a hand-written native `SerializerV2` that writes the same bytes under the same id (#8688, #8691, #8692). Other hot Remote serializers (SystemMessage, MessageContainer, cluster heartbeats) may take the same route later.
- Migration order (hot-path + low-risk first, durability and correctness-critical last): ReliableDelivery (36→76) → DistributedData (12→52, 11→51) → Cluster tools (PubSub 9→49, ClusterClient 15→55, Singleton 14→54) and Metrics (10→50) → Sharding (13→53, as a unit) → Cluster core (5→45). Remote core (16, 22, 6, 3), Persistence (7, 8, 17: native route) and the stream-ref protocol (30→70) are now in the same epic (#8675).
- Once the switch is on, v1.6 nodes write MessagePack for the migrated subsystems. Rolling-upgrade safety between v1.6 nodes is unconditional (both serializers always registered, reads dispatch by id); a v1.5→v1.6 roll keeps the switch off until every node runs v1.6 — **not** a new framework `AppVersion` gate or remoting-handshake capability field.
- Add a benchmark acceptance gate: extend `ClusterMessageSerializerBenchmarks`, `DDataSerializationBenchmarks`, the DData CRDT serializer benchmarks, and the `RemotePingPong --serializer` harness to A/B legacy vs. MessagePack-v2 per subsystem, measuring CPU, allocations, and payload size on the same hardware, same run. Benchmark results govern *when the switch is recommended for a subsystem* and where optimization effort goes; they do not split subsystems — each subsystem migrates as a unit, with no per-message-type hybrid (design.md Decision 9, as amended).
- Process: breaking changes go in each PR body under `## Breaking changes` and are batched into `BREAKING_CHANGES_V1.6.md` later. Every serializer PR body also has `## Generator gaps found` and `## Generator changes made`. Generator gaps get fixed in the generator in separate small PRs.
- Long-term direction (maintainer, 2026-07-18): migrate everything to MessagePack uniformly so the protobuf **write** paths can eventually be deleted and, once durable-store migration tooling exists, the `Google.Protobuf` dependency can ultimately be dropped in a future major version. Legacy **read** support remains for the whole v1.6 cycle (rolling upgrades + durable data are read-forever).

### What Does Not Change

- Legacy serializers, ids, and wire formats stay in the codebase and are read forever.
- Nested arbitrary **user** payloads keep their own serializers — only the wrapper (`Payload`/`OtherMessage`/`SequencedMessage`) encoding changes; the (serializerId, manifest, bytes) nesting contract is preserved.
- Durable/persisted state migrates going forward, not retroactively: durable stores become self-describing so new writes may be MessagePack while old records read as legacy forever, with no bulk rewrite of history (persistence rule from `messagepack-sourcegen-validation` design.md Decision 8.1). Akka.Persistence stamps the serializer id of each **payload** inside a journal event or snapshot (covers Sharding remember-entities and Akka.Delivery's durable queue). It does **not** stamp the **outer** record in several plugins (Redis, MongoDB default mode, Azure, `LocalSnapshotStore`), which read it back by type binding. So PersistenceMessage (7) and PersistenceSnapshot (8) keep their bytes and ids (native route). DData's `LmdbDurableStore` is headerless today and gains a `(serializerId, manifest)` header as a prerequisite (#8716), treating headerless records as legacy protobuf (design.md Decision 11).
- No new serialization dependency: MessagePack-CSharp via the existing `Akka.Serialization.V2` generator is the settled choice.
- No framework-enforced `AppVersion` or capability-version handshake gate is added; rollout safety is operator-discipline plus documentation, matching the `widen-system-uid-to-64bit` precedent.

This change supersedes, for the specific subsystems and message shapes listed above, the "protobuf wrapper wire formats are not replaced by default" non-goal recorded in `messagepack-sourcegen-validation/design.md` (Goals / Non-Goals, line 30) and mirrored in that change's `proposal.md` ("What Does Not Change"). That non-goal held while the generator itself was being validated; this change is the follow-on migration built on top of the validated generator, with each subsystem's write format moving to MessagePack when the global switch is on. Durable/persisted wire formats that cannot signal their writer (Persistence outer records) remain unchanged.

## Capabilities

### New Capabilities

- `messagepack-internal-serializers`: forked MessagePack V2 serializers for ReliableDelivery, DistributedData, Cluster Tools (PubSub/ClusterClient/Singleton), Metrics, Sharding, Cluster core, Remote core and the stream-ref protocol, registered as read-only rows in the modules' C# tables and writing when the global opt-in switch is on, with legacy serializers registered forever for reads and user bindings as the operator pin; native same-bytes serializers for Primitive, PersistenceMessage and PersistenceSnapshot; the reserved 40-79 serializer-id block; and the benchmark acceptance gate that governs switch-on readiness.

### Modified Capabilities

None. `openspec/specs/` has no existing entries for the touched subsystems (DistributedData, Delivery, Cluster Tools, Sharding, Cluster core serializers predate OpenSpec adoption for this repository), so there is no baseline requirement set to delta against. Subsystem-level code impact is captured under Impact below instead of as formal capability deltas.

## Impact

- New source-generated `*MessagePackSerializer` types + `[AkkaSerializable]` DTO mirrors in `Akka.Cluster` (ReliableDelivery, Cluster core), `Akka.DistributedData`, `Akka.Cluster.Tools`, `Akka.Cluster.Metrics`, `Akka.Cluster.Sharding`, `Akka.Remote`, `Akka.Streams` (protocol messages). Types that live in `Akka.dll` use the hand-written wrapper + generated codec pattern from PR #8409.
- Shared wire fragments (`UniqueAddress`, `VersionVector`) as hand-written formatters or one shared cross-assembly `[AkkaSerializable]` fragment (design.md Decision 10, G-5), extending the existing `AddressFormatter`/`ActorPathFormatter` precedent.
- New read-only rows in each module's `<Module>Serializers` C# table. **No `.conf` rows.** The module table approval snapshot (`SerializerTableSpec`, PR #8711) shows each row.
- A global opt-in V2 switch (HOCON key plus `Setup` equivalent, #8713). One prerequisite code change: `LmdbDurableStore` gains a self-describing per-record header so DData durable data recovers by stored format (headerless = legacy protobuf) rather than by the current binding (#8716).
- Generator work shared by several ports: formatters in collection positions and native `TimeSpan`/small scalars (#8715).
- API-approval baselines updated for new serializer types (largely `internal`) and for the native `SerializerV2` rewrites of Primitive, PersistenceMessage and PersistenceSnapshot.
- Breaking changes recorded in each PR body (`## Breaking changes`), batched into `BREAKING_CHANGES_V1.6.md` later.
- New/extended benchmarks: `ClusterMessageSerializerBenchmarks`, `DDataSerializationBenchmarks`, DData CRDT serializer benchmarks, `RemotePingPong --serializer` harness.
- Operator-facing documentation: runbook with when to turn the switch on, how to roll back, and the per-subsystem alias table for pins.
